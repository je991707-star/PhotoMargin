# 文字邊界、下方邊距與間隔定位

## 底部空白過大的實際原因

1. 原 LayoutEngine 在照片寬度限制成立後，仍將「照片＋指定間隔＋資訊」整組垂直置中，剩餘高度的一半變成額外底部空白；下方數值只是最低限制，不是實際定位目標。
2. 原 CropGeometry.TextSafeRect 對裁切可見區執行 Inset，同時內縮上下左右；水平文字留白也意外往上推了文字底部。
3. 預設與舊預設自動啟用 4:5＋5:4，後者會額外限制上下。1080 畫布的 5:4 可見底邊是 972，再內縮 24 後是 948，即使底部數值為 0 仍有至少 132px 的限制。

沒有發現 Renderer 加入另一層固定底部 padding，也沒有固定高度的資訊容器。缺值項目已在核心過濾；字體量測的每側 1px guard 是保護抗鋸齒與降部的最小餘量，保留而不靠裁切貼底。

## 名稱與行為

- **文字與左右邊界**：從啟用裁切的可見區左右向內縮，不修改上下。
- **下方邊距**：資訊可見文字外框聯集的底邊定位目標。以既有 guard 保護字形，0 時只多約 1–3 個實際輸出像素，不保留大段固定留白。明確啟用的上下裁切仍優先。
- **照片與文字間隔**：照片底邊至最上方文字外框的垂直距離，不因下方邊距改變而被偷偷拉開。
- **焦距、曝光三要素間隔**：焦距、光圈、快門、ISO 可見項目間的水平距離，字距、行距及缺值過濾維持不變。

標籤、AutomationProperties.Name、Tooltip、核心驗證訊息及目前文件已同步；沒有增加控制項。長標籤沿用原生 TextBlock 換行避免窄欄裁切。

## 共用排版

```text
安全區左右 = 裁切可見區左右 ± 文字與左右邊界 × Scale
文字底部目標 = min(裁切可見區底邊, OutputSize − 下方邊距 × Scale)
資訊高度 = max(實測文字外框底邊) − min(實測文字外框頂邊)
文字頂部 = 文字底部目標 − 資訊高度
照片底部 = 文字頂部 − 照片與文字間隔 × Scale
照片可用高度 = 照片底部 − 上方邊距 × Scale
```

照片依可用寬高完整等比例 contain，資訊依量測外框平移，不再整組垂直置中。照片仍水平置中；沒有資訊時才維持照片垂直置中，不預留空資訊或間隔。無效安全區、照片空間不足及文字重疊／越界仍拒絕輸出。

預覽與 PNG／JPG 匯出共用 LayoutEngine 及 ImageRenderer。輔助線現在只繪製實際啟用的裁切，不再預設顯示未啟用的 5:4 橫線；VisibleRect 的通用比例幾何不改。

## 格式 7 遷移

保留原有 JSON 鍵（bottomSafeDistance／bottom、cropExtraPadding／extra、photoInfoGap／gap、exposureItemGap），原 ID、名稱及八組數字不重設。僅對版本 2–6 的雙 true 保護移除自動 5:4；舊設定頁沒有明確選用 5:4 的入口，雙 true 視為舊自動預設。舊格式無選用來源紀錄，因此手動編輯 JSON 的雙 true 無法區分，也會套用此規則；單獨 5:4 保留，版本 7 的明確組合不再改動。成功保存才寫新版，讀取失敗保護、草稿隔離、另存、取消、刪除勾選確認維持原行為。
