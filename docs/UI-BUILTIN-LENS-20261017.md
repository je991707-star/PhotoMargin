## 遷移

### 內建表未更新的修復

實際安裝資料已是格式 8、`builtInRevision=1`，但八組仍全部保存 `Side=48, Top=100, Bottom=50, Gap=50, ExposureItemGap=18, Extra=24`。第一版的嚴格舊值比對為保護修改而跳過它們，卻仍把整份預設標記為已遷移；外層 `Version < 8` 又讓後續啟動永遠不再檢查。因此新安裝測試雖通過，既有使用者仍讀到舊表。

修復版將內建表修訂號與 JSON 格式版本分離。revision 0 仍採下述逐組保留邏輯；revision 1 則一次更新為 revision 2 的正確八組表。若 revision 1 內容與新表不同，先完整複製成唯一名稱的「更新前備份」自訂預設，保留八組數值及保護；已有自訂 ID、名稱與資料不變。內建 ID 仍為 `default`，沒有第二份內建入口。若值本來已正確，只更新修訂號，不建立備份。revision 2 後的使用者編輯不再自動覆寫。

目前作品若仍等於被選取的舊內建 4:3／目前排列副本，連同更新；若另有手動版面調整則保留。字級、EXIF、輸出偏好不改。成功保存後重啟不重複備份，也不重設新草稿。修復後執行包與結果見 `docs/UI-BUILTIN-FIX-20261017.md`。

格式 8 接受 2–7，沿用原序列化鍵及穩定 ID。舊版先完成既有保護／比例資料正規化，再按配置比對：只有內建 ID 的完整配置等於舊值 `Side=48, Top=36, Bottom=72, Gap=24, ExposureItemGap=18, Extra=24, Portrait=true, Landscape=false` 時更新為對應新值；改過任一數字或保護就整組保留，不做逐欄混合。自訂 ID 一律不套新表，名稱保留。

只有仍是舊內建未修改副本的作品快照才同步更新；字體、手動資料與輸出偏好不改。匯入新照片時，也只在作品數值仍等於目前選取預設的副本時，依校正後的來源比例套用相應組；手動邊距保留。判斷在取得渲染閘門後才進行，避免等待期間的新輸入被覆蓋。

成功保存後寫入版本 8 與內建 revision，不每次啟動覆寫。已有空清單不重建、既有內建不重複插入。使用者日後刻意把數字改回舊值也不再次升級。

## 鏡頭字級

- 新建預設字級 **16px**，範圍 **8–100px**；既有保存的有效字級原值保留。
- 主畫面鏡頭 ComboBox 使用獨立選項，不降低機身、資訊及日期的 18px 下限。設定頁沒有鏡頭字級控制項，不新增重複入口；其預覽沿用主畫面字體設定。
- ViewModel、LayoutSettings.Validate 及 LayoutEngine 全部使用新的鏡頭範圍；不再以共用 MinimumFontSize 拉高鏡頭。
- 原生 TextSubmitted 處理輸入值與選取同步；小數值補進同一選項資料來源，無效文字恢復原值。
- **依使用者確認，不新增自動縮字**。指定字級原樣量測／渲染，仍放不下時沿用換行／置中回退或安全錯誤；不截短原鏡頭名稱，不使用固定 18px 行高。
- 1080／2048 仍只依 OutputSize/1080 換算，與視窗 DPI 無關。

## 修改檔案與驗證

App：`BuiltInMarginPresets.cs`、`MarginRule.cs`、`SettingsStore.cs`、`MainViewModel.cs`、`MainWindow.xaml/.cs`；Core：`LayoutModels.cs`、`LayoutEngine.cs`。規則仍只保存版面數值，不把全域字體硬塞入八組預設。

測試涵蓋八組六欄逐一比對、舊格式逐版遷移、局部編輯及自訂 ID 保護、原作品保留、版本 8 不重覆遷移、8／12／16／18 的實際字形量測與 PNG／JPG／預覽，以及 12px 保存還原。

原生 Debug 測試入口為 `--verify-builtin-lens` 與新程序 `--verify-builtin-lens-restore`；使用獨立偏好與測試照片，不修改使用者設定。成品與證據放於 `artifacts/PhotoMargin-builtin-lens-verification/`。
