# 2026-10-20 匯出功能

## 實作

- `ExportPreferences` 是獨立匯出偏好；輸出尺寸沿用目前作品的 `LayoutSettings.OutputSize`，與八組版面預設的配置無關。主畫面與設定頁使用同一個 MainViewModel，不建立第二份尺寸或品質狀態。
- 主畫面安全線／格式／尺寸與品質保留原生控制項；無照片也可調整偏好。照片相關控制項繼續反灰。
- 匯出設定分為格式與尺寸、儲存、拍攝資訊、完成後四組，原生垂直捲動，沒有新增全域入口。
- `ImageRenderer.RenderExport` 共用完整尺寸 Compose；JPG、PNG、WebP（一般／無損）只在最後編碼分流。PNG 固定壓縮設定，不使用品質百分比。WebP 一般模式明確關閉 lossless，即使品質 100 也不偷換模式。
- 清除合成影像的 metadata，重新附上 sRGB ICC，僅在開啟拍攝資訊時建立白名單 EXIF。使用目前有效／手動欄位，不複製原始 EXIF。方向設為 TopLeft；不輸出 GPS、縮圖及舊尺寸。ISO 超出目前 16-bit EXIF 寫入範圍會明確阻止匯出，不假裝保存成功。日期／時間不完整時也明確提示。
- PNG Strip 會留下 include-chunk artifact，因此需明確重新指定 iCCP／eXIf，並保留 ICC，而非僅寫 sRGB chunk。參考 [ImageMagick PNG 編碼器](https://github.com/ImageMagick/ImageMagick/blob/main/coders/png.c) 與 [defines 說明](https://imagemagick.org/defines/)。
- 匯出開始先凍結格式、品質、版面與有效拍攝資訊；背景重新計算完整尺寸安全區。原子 rename 前持有來源／RAW 讀取鎖並驗證檔案身分；RAW 已移走時不要求重新讀取。自動編號以 no-overwrite rename 處理競爭，詢問模式在確認到編碼完成期間鎖定目標，最後重新驗證同一檔案身分。來源檔保護不受同名策略影響。
- 失敗／取消清理本次暫存，成功後讀取實際檔案大小，保存位置或開啟資料夾失敗不將已完成的圖片宣稱為匯出失敗。
- 儲存檔案使用目前 SDK 的 `Microsoft.Windows.Storage.Pickers.FileSavePicker`，只回傳路徑，不使用會建立空白占位檔的舊 UWP SavePicker。關閉 picker 自帶覆寫提示，統一由目前同名策略決定編號／確認／覆寫。參考 [Windows App SDK 官方規格](https://github.com/microsoft/WindowsAppSDK/blob/main/specs/Storage.Pickers/Microsoft.Windows.Storage.Pickers.md)。

## 遷移與部署

- 設定格式 9 → 10；接受舊版本 2–9。沒有 Export 欄位時，從舊 Layout.JpegQuality 和 LastOutputDirectory 遷移；輸出尺寸不變。預設 JPG95、WebP95、WebP有損、自動編號、拍攝資訊關閉、開啟資料夾關閉、記住位置開啟。八組配置、預設 ID／名稱及 RAW 快照不受影響。
- 關閉記住位置時不將選取目錄寫入設定檔（當次執行仍可用）；舊 LastOutputDirectory 同步清除。
- 沿用 Magick.NET-Q8-x64 14.16.0 的原生 PNG／JPEG／WebP 編碼器，無新增 NuGet 或外部程式，發布繼續包含既有原生依賴。

## 驗證

Release 核心 59、影像 47、App 邏輯 99，共 205 項測試全通過、無略過，包含指定 GH5 RW2／修好 JPG 的實檔測試。新增測試涵蓋編碼格式／尺寸、三種格式白名單 metadata 與 ICC、Unicode metadata、PNG／WebP 無損像素一致、品質 1、命名清理／編號／取消、來源／RAW 保護、舊設定遷移、品質分離、匯出快照、RAW 與手動有效欄位寫入及覆寫確認取消。

Windows 原生測試使用獨立設定與發布目錄；1344×892、1100×760，DPI 120（125%），檢查空作品偏好可編輯、格式條件顯示、跨頁同步、垂直捲動、深淺主題及真實 JPG 的三種格式匯出。最終跨程序匯出回歸 14 項、既有主畫面／設定導覽／安全線與匯出回歸 149 項，共 163 項通過。截圖與 JSON 結果置於 `artifacts/PhotoMargin-export-debug-win-x64`。

尚未人工操作系統檔案／資料夾選擇器、Explorer 開啟資料夾，以及 100%／150%／200% DPI、高對比及完整鍵盤／螢幕閱讀器驗收。使用原生控制項與既有焦點／主題行為，不將編譯或程式化測試當成這些人工驗收已完成。
